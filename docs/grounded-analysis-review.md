# 근거 중심 분석과 비판적 재검토

## 적용 범위

- 국내 AI 가상매매와 국내·미국 PC 외부 작업자가 재사용하는 `OllamaExperiment.decide`: 위험 설명에 실패 가설·조기 경고·판단 철회 조건을 요청하고, 출력 전 숫자·시각·통화·주장을 재검토한다. 기존 Decision 출력 형식과 모의매매 동작을 유지한다.
- `research_agent.analyze`를 사용하는 단일 종목 과거 분석: 최대 세 가지 가정 시나리오와 OHLC/거래량 숫자 근거를 구조화한다. 인용 날짜·종목·필드·값을 입력과 대조하고 불일치 시 거부한다.
- 저장된 이전 ResearchBrief는 새 배열 필드의 기본값으로 계속 읽을 수 있다. 입력이 부족하면 빈 배열과 한계 설명을 허용한다.
- 상위50 배치 분석은 별도 프롬프트이므로 이번 변경 대상이 아니다.

숫자 근거 필드의 일치는 기계적으로 검증하지만 자유서술의 의미, 계산 과정 전체, 자료 자체의 진위는 보장하지 않는다. 검사관 역할은 동일 추론 안에서 수행하며 별도 모델이나 추가 API를 호출하지 않는다. 기존 Ollama 요청의 출력이 길어질 수 있다. 추론 정확도·수익률 향상은 측정하지 않았으며 보장하지 않는다.

## 정리 후보 검토

삭제는 수행하지 않았다. 사용 빈도와 운영 자료는 확인하지 못했으므로 아래는 코드 구조 기준 후보다.

| 후보 | 판단과 권장 조치 |
|---|---|
| `app/experiments/api.py`의 고정 `/status` | 학습 코드가 존재해도 항상 학습 불가·모델 없음으로 응답한다. 기능 삭제보다 상태 의미를 데이터 검사 전용으로 정정하거나 실제 결과 상태와 통합하는 것이 우선이다. |
| `scripts/ollama_history.py`와 `scripts/top50_experiment.py` | 과거 입력 구성·로지스틱·추론·평가 책임이 겹친다. 단일 종목과 다종목 흐름은 유지하되 공통 유틸리티로 통합할 후보다. |
| 수동 뉴스 입력·수동 가격 테스트 | 실사용 조회 화면에서는 부가 도구로 충분하다. 회귀 검증과 장애 재현에 유용하므로 내부 테스트 기능은 유지한다. |
| `scripts/check_*_ui.py` 네 파일 | 서버·로그인·화면 캡처 준비가 반복된다. 공통 테스트 도구로 묶을 수 있으나 검증 범위 자체는 유지해야 한다. |
| `requirements-mcp.txt` | requirements.txt를 재사용하는 호환 진입점이다. CI와 문서에서 참조하므로 지금 지우면 깨질 수 있다. |
| OpenAI 뉴스 분석 선택 경로 | 새 MCP가 OpenAI API를 쓰지 않는 것과 별개인 기존 선택 기능이다. 실제 사용 여부와 비용 정책 확인 후 비활성화·제거 여부를 결정한다. |

모의매매 격리, 사용자별 저장소, 인증·MCP 권한 검증, 주문 중복 방지와 테스트는 유지 대상이다. 현재의 위험 관리·실제 시세 모의 손절·연속 낙폭 기록 보완은 프롬프트 정리보다 우선적인 별도 작업이다.
